# Karvinen 2026: Sudo without password

- Artikkelissa kerrotaan, miten käyttäjälle annetaan mahdollisuus käyttää sudo-komentoja ilman salasanan kysymistä.
  
- Käyttäjä lisätään sudoless-ryhmään.
  
- Tiedostoon /etc/sudoers.d/sudoless lisätään sääntö %sudoless ALL = (ALL) NOPASSWD: ALL.
  
- visudo-komennolla voidaan muokata sudo-asetuksia turvallisemmin, koska se tarkistaa syntaksivirheitä.
  
## Oma huomio:

- Salasanaton sudo helpottaa automaatiota, mutta on tärkeää huolehtia siitä, ketkä kuuluvat sudoless-ryhmään.

# Karvinen 2026: Passwordless Sudo with Ansible

- Artikkelissa näytetään, miten salasanaton sudo määritetään automaattisesti Ansiblella.
  
- Ansible-rooli luo käyttäjän antero ja ryhmän sudoless.

- Käyttäjälle lisätään SSH-julkinen avain.

- Ansible luo sudoers-säännön, jolla sudoless-ryhmän jäsenet voivat käyttää sudoa ilman salasanaa.

- Artikkelissa korostetaan, että ensin kannattaa opetella tekemään määritys käsin ja vasta sen jälkeen automatisoida se.

## Oma huomio:

- Ansible helpottaa asetusten tekemistä useille palvelimille. Mietin, miten paljon aikaa säästyy, jos samoja käyttäjiä ja oikeuksia pitää määrittää monelle palvelimelle.

# Ansible dokumentaatio


# Copy

- copy-moduulilla voidaan kopioida tiedostoja tai kirjoittaa sisältöä tiedostoon toisella palvelimella.

## Keskeiset optiot:

- content: määrittää tiedostoon kirjoitettavan sisällön.

- dest: määrittää tiedoston kohdepolun.

- src: määrittää kopioitavan tiedoston lähteen.

- owner: määrittää tiedoston omistajan.

- group: määrittää tiedoston ryhmän.

- mode: määrittää tiedoston käyttöoikeudet.

## Esimerkki:

- name: Create a file
  ansible.builtin.copy:
    content: "Hello world!"
    dest: /tmp/hello.txt
    owner: antero
    group: antero
    mode: "0644"


# apt

- apt-moduulilla hallitaan Debian- ja Ubuntu-palvelimien ohjelmapaketteja.


## Keskeiset optiot:

- name: määrittää asennettavan paketin nimen.

- state: määrittää paketin halutun tilan, esimerkiksi present tarkoittaa, että paketin pitää olla asennettuna.

- update_cache: päivittää pakettien listauksen ennen asennusta.


## Esimerkki:

- name: Install curl
  ansible.builtin.apt:
    name: curl
    state: present
    update_cache: true


  # file

  - file-moduulilla hallitaan tiedostojen ja hakemistojen ominaisuuksia, kuten käyttöoikeuksia ja omistajia.
 

  ## Keskeiset optiot:

- path: määrittää tiedoston tai hakemiston sijainnin.

- recurse: määrittää, sovelletaanko asetuksia myös hakemiston sisältöön.

- src: määrittää lähteen esimerkiksi symbolista linkkiä luotaessa.

- state: määrittää halutun tilan, esimerkiksi directory, file, link tai absent.

- owner: määrittää omistajan.

- group: määrittää ryhmän.

- mode: määrittää käyttöoikeudet.


## Esimerkki: 

- name: Create directory
  ansible.builtin.file:
    path: /tmp/harjoitus
    state: directory
    mode: "0755"


# user

- user-moduulilla luodaan ja hallitaan Linux-käyttäjiä.

## Keskeiset optiot: 

- name: käyttäjän nimi.

- create_home: määrittää, luodaanko käyttäjälle kotihakemisto.

- comment: käyttäjän lisätiedot.

- groups: määrittää ryhmät, joihin käyttäjä lisätään.

- shell: määrittää käyttäjän komentotulkin.

- state: määrittää, onko käyttäjä olemassa (present) vai poistetaanko se (absent).

- system: määrittää, luodaanko järjestelmäkäyttäjä.

## Esimerkki: 

- name: Create user
  ansible.builtin.user:
    name: testi
    create_home: true
    shell: /bin/bash
    state: present


  # authorized_key

  - authorized_key-moduulilla lisätään käyttäjälle SSH-julkinen avain, jonka avulla käyttäjä voi kirjautua palvelimelle ilman SSH-salasanaa.
 

  ## Keskeiset optiot:

- user: käyttäjä, jolle avain lisätään.

- key: lisättävä julkinen SSH-avain.

## Esimerkki: 

- name: Add SSH key
  ansible.posix.authorized_key:
    user: antero
    key: "{{ lookup('file', '/home/käyttäjä/.ssh/id_ed25519.pub') }}"

# Sudoless. Tee ansiblea varten tunnus, jolla voi käyttää sudoa ilman salasanaa. Sekä ssh-kirjautuminen että sudon käyttö tulee olla ansbilea varten automatisoitu.#

- aloitin tehtävän tarkistamalla, että ansible toimii komennolla: `ansible --version` <img width="1634" height="376" alt="image" src="https://github.com/user-attachments/assets/cb733350-704f-4b02-bf7d-4f009b8b6cce" />
- lisäsin Upcloudiin toisen debian palvelimen, jota käytän tehtävässä hallittavana orjakoneena.
  
- Kirjauduin pää koneelta orjakoneelle SSH-yhteydellä.
  
- Tein orjakoneelle uuden käyttäjän nimeltä antero komennolla: `adduser antero`
  
- Lisäsin käyttäjän sudoryhmään komennolla: `usermod -aG sudo antero`
  
- Tämän jälkeen tarkistin ryhmät komennolla: `groups antero` <img width="838" height="184" alt="image" src="https://github.com/user-attachments/assets/4cd93776-8a58-42be-aae2-a7b177918926" />

- Tämän jälkeen määritin käyttäjälle salasanattoman sudo-oikeuden luomalla tiedoston /etc/sudoers.d/antero komennolla: `visudo -f /etc/sudoers.d/antero`
  
- Lisäsin tiedostoon seuraavan rivin: `antero ALL=(ALL:ALL) NOPASSWD:ALL`
  
- Tämä mahdollistaa sen, että antero voi suorittaa komentoja pääkäyttäjän oikeuksilla ilman salasanan kysymistä.
  
- Seuraavaksi kopioin pää koneen julkisen SSH-avaimen orjakoneelle ja lisäsin sen käyttäjän antero tiedostoon ~/.ssh/authorized_keys. Näin sain SSH-kirjautumisen toimimaan ilman salasanaa.
  
- Testasin yhteyden ja sudo oikeudet. SSH-yhteys onnistui komennolla: `ssh antero@80.47.238.169` <img width="1620" height="366" alt="image" src="https://github.com/user-attachments/assets/033011d2-1fa8-46d3-a6cc-e5b26d212343" />

- Salasanattoman sudon testasin komennoilla: `sudo -k` ja `sudo -n whoami`
  
- Komento tulosti root, joten salasanaton sudo toimi oikein. <img width="1620" height="366" alt="image" src="https://github.com/user-attachments/assets/7b177861-9655-4ddf-93eb-7933bdb9f433" />
